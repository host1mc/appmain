Nodes

The hosts /panel deploys containers onto. Nothing lets anyone pick a node for a particular server — a new container goes to the lowest-numbered node that is enabled, has capacity above zero and has room — so capacity and enabled are the whole of the placement control. Existing containers are never moved, which is why a node is retired by setting its capacity to 0 rather than deleted.

Servers on a row lists what is actually on that node: every container placed there, the panel user who owns it, the state it is supposed to be in, and the state the node reports it is really in. The rows come from the database and the live states come from the node itself, so a server whose container was removed by hand, and a container nobody owns any more, both show up as the faults they are.

Config on a row asks that node what it is actually configured to enforce — memory and CPU per container, whether its Docker daemon is up, which runtimes it offers, how large an upload it accepts. Those settings live in that host's own environment, not in this database, so the answer is read live from the agent every time the panel is opened. Nothing here is a copy: a limit shown is a limit the node applies.

Pending container deletions

Servers deleted while their node was offline. The owner's slot is already freed, but the container is still on that node — and nothing removes it automatically, so nothing is lost until an operator confirms it here. Delete from node removes the container and its data on the node; Remove entry only clears the queue row, for a container you already removed by hand on the host.

Register a node

The console never talks to a node itself. It posts to the engine, which is the only process that owns the node table — it encrypts the agent token before storing it, so the token below is write-only from here on and no page ever gets it back.

1–64 characters, and unique regardless of case.
Filled in for whichever address below was typed without one. An address that carries its own http:// or https:// keeps it, so one half of a pair can stay plain while the other is TLS.
A bare origin — scheme, host and port only, no path. The address most app instances use, normally the node's public hostname. Plain http:// to anything but loopback puts the agent token on the wire in the clear; it is allowed, and it is warned about.
A second address for the same agent, for the app instance the first one does not work from. An instance sharing this node's host has to come in over loopback, because the public hostname does not come back from inside that host. Both addresses go on one node row — its capacity is counted once and there is one container pool — and /panel tries them in order and uses whichever answers. Leave it empty for a node every instance reaches the same way.
The node-agent's bearer token. It grants full control of that host's container daemon. Stored encrypted; a value that is already ciphertext is stored as-is, so a token copied out of token_enc can be pasted back.
How many containers may live here. Required, because there is no sensible guess: 0 registers the node and takes it out of placement, and a number is the ceiling new deploys are measured against.
