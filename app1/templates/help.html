1 Status bot setup, start to finish

  1. Create a Discord application in the Developer Portal, open the Bot tab, and copy the token. Keep it private — anyone holding it controls your bot.
  2. Invite the bot to your server with the OAuth2 URL generator: scopes bot, permissions View Channel, Send Messages and Read Message History. It needs nothing else — no administrator, no kick, no ban.
  3. Make a free account here, open the panel, and paste the token into a new bot slot. It is encrypted before it is stored and never shown back to you.
  4. Point it at your server: the public IP or hostname plus port — 25565 for Java, 19132 for Bedrock. We query the public status endpoint only; no RCON, FTP or plugin is needed.
  5. Paste the guild ID and channel ID (enable Developer Mode in Discord, right-click, Copy ID). The engine posts one embed, then edits that same message on your refresh interval.
  6. Press Start. The engine picks the bot up on the next tick and the embed goes live.
Never paste your bot token in Discord, email, or a help ticket. If one leaks, reset it in the Developer Portal and paste the new token into the panel.

2 Designing the status embed

Open any bot slot to reach the embed builder. The preview on the right renders exactly what Discord will show, and every change appears there before you save.

  • Title, description and footer accept Discord markdown: **bold**, *italic*, __underline__, ~~strike~~, `code` and [links](https://…).
  • Widgets are the live fields — status, MOTD, IP and port, players online, player list, version, software, plugins, and timestamps. Drag them to reorder; each renders in sequence.
  • Placeholders like {ip_port} expand when the reply is sent, so one template serves every server.
  • Refresh interval minimum is 15 seconds; 60 seconds suits almost every server and is gentler on your Minecraft host and Discord's API.
  • IP replies: set a trigger word (for example ip) and the bot answers with your address as a plain message or a styled embed.

3 Deploying your own app

The same panel hosts code you wrote yourself. Pick a runtime, set a start command, deploy — the container runs around the clock.

  1. Open the panel's Deploy server page and name the container.
  2. Pick a runtime and version: Node.js, Python, Ruby, Go, PHP or Bun. Only versions the node can actually build are offered.
  3. Set the startup command that runs inside /home/container — for example node index.js or python bot.py.
  4. Upload files or let the dependency step run (npm install, pip install -r requirements.txt), then create and start the server.
  5. Watch the live console and the files tab to confirm it booted; memory, CPU, storage and network meters show what it uses.
Outbound networking only: your app can reach Discord, an API or a database, and nothing on the internet dials in to it. There is no inbound port, domain, or TLS to configure.

4 Weekly renewals, explained

Free accounts stay live with a one-click renewal each cycle. A few days before the turn-off date a Renew button appears on your home page and in the hosting panel — press it and the deadline moves a full cycle past the old expiry. The button hides again until the next window opens, so you cannot renew twice by accident.

  • Renewing also restarts anything the inactivity policy had paused.
  • Paid accounts never need to renew.
  • Miss the window and workloads stop; renewing brings them back.

5 Fixing the common problems

  • Embed stuck or not updating: check the bot is Started in the panel, then confirm the Minecraft IP and port answer from your own connection. A changed server IP is the usual cause.
  • Server shows offline but is up: the status query may be blocked by the host's firewall, or the server lists a different port than the one you entered. Bedrock servers must use the Bedrock port.
  • Bot has no permission: re-check View Channel, Send Messages and Read Message History on the status channel — then re-invite with the corrected URL.
  • Own app restarts in a loop: read the first lines of the live console; missing dependencies and wrong start commands announce themselves there. Reinstall dependencies from the server settings if the install step was skipped.
  • Login trouble: registration codes arrive by email and expire quickly — check spam, then request a fresh one.
Still stuck after the list above? Ask in the Discord with your bot name, what you expected, and what you see instead — that is everything needed to help.

6 Quick answers

Is everything here really free?

Yes. No paid tier exists. The public pages carry ads, which is what pays for the servers — see how the service is funded.

Do you support Bedrock?

Yes — player count, version, MOTD and player lists work for Java and Bedrock alike.

Can I run code that isn't a Discord bot?

Yes. Web services, Telegram bots, scrapers and scheduled jobs all run, within the container's memory, CPU and disk limits shown at deploy time.

How do I delete everything?

Delete the account from the panel. Bots stop and the stored data is removed, as described in the Privacy Policy.
